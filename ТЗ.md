# SoundCloud Sync — краткое ТЗ

## Цель и платформы

Сервис для совместного прослушивания SoundCloud: создать комнату, отправить ссылку, добавить музыку в очередь и слушать вместе.

MVP: единый веб-клиент для Linux и Windows, работающий в актуальных Chrome/Chromium и Firefox. Установка приложения не обязательна. Отдельные desktop-сборки можно добавить позже; мобильные клиенты в MVP не входят. Начальный сценарий — два слушателя, архитектура допускает больше участников.

## Обязательные функции

- Комната по ссылке, вход по имени без регистрации. Список участников и их состояния: слушает, пауза, загрузка, ждёт остальных, нет связи.
- Общая очередь. Каждый участник может добавлять, удалять и переставлять ещё не начавшиеся позиции. Уже играющий трек меняется отдельной командой «Следующий».
- Добавление по ссылке отдельного трека, целого плейлиста или альбома SoundCloud. Коллекция разворачивается в отдельные позиции в исходном порядке; частичную выдачу нужно дочитывать полностью. Название коллекции сохраняется у её треков. Повторное добавление музыки разрешено.
- Импорт коллекции публикуется в очередь одной операцией. Показываются результат импорта и список недоступных позиций; ошибки не проходят молча.
- Общие Play / Pause и «Следующий», доступные любому участнику. Громкость индивидуальная. Состояние кнопок подтверждает сервер.
- После обрыва связи клиент восстанавливает комнату и очередь. Вход посреди трека предлагает присоединиться к текущей позиции; для новичка допустима однократная перемотка.

## Синхронизация: выравнивание между треками

Приоритет — непрерывное прослушивание текущего трека. Автоматических перемоток и изменения скорости для устранения накопленного рассинхрона во время трека нет. Небольшой рассинхрон допускается.

1. Сервер задаёт текущую позицию очереди и идентификатор запуска `playbackId`. Клиенты загружают только выбранный трек и подтверждают готовность; самостоятельный переход плеера дальше запрещён.
2. Когда участники готовы, сервер назначает время начала `startAt` по своим часам с небольшим запасом. Клиенты оценивают разницу часов через ping/pong. Точность встроенного плеера проверяется прототипом; старт не обещает точности до миллисекунды.
3. По окончании трека клиент отправляет `ended(playbackId)` и остаётся в тишине со статусом «Ждём остальных». Отстающие спокойно дослушивают.
4. Когда закончили все активные участники, сервер переводит комнату к следующей позиции, снова собирает готовность и назначает общий старт. В конце очереди воспроизведение останавливается.
5. Общая пауза действует и в фазе ожидания/подготовки: отменяет назначенный старт. Play продолжает текущий трек у тех, кто ещё слушает; закончившие продолжают ждать. При подготовке следующего трека Play возобновляет процедуру общего старта.
6. «Следующий» явно прерывает текущий трек у всех и запускает подготовку следующего, без ожидания дослушивания.

Защита от вечного ожидания: heartbeat каждые 5 секунд, потеря связи после 15 секунд. Ожидание окончания отстающих — до 30 секунд с первого `ended`; ожидание готовности — до 20 секунд. Значения настраиваются. По таймауту неготовый участник временно исключается из барьера, остальные продолжают. Он видит причину и может присоединиться к текущей позиции или дождаться следующего трека. Недоступный всем трек пропускается с сообщением. Подключившийся посреди трека не задерживает комнату, пока не подтвердит участие в воспроизведении.

## Архитектура сервера

```text
Linux / Windows: браузер + интерфейс + SoundCloud Widget
       │ HTTPS: комнаты, импорт ссылок
       │ WSS: команды, состояние, готовность, heartbeat
       ▼
Node.js + TypeScript + Fastify + WebSocket
       ├─ Rooms: участники и доступ по токену комнаты
       ├─ Queue: импорт и последовательные изменения очереди
       ├─ Playback: состояние и барьеры окончания/готовности
       ├─ SoundCloud adapter: метаданные треков и коллекций
       └─ SQLite: очередь, комнаты, снимок состояния

Звук: SoundCloud → каждый клиент напрямую
```

- Один процесс сервера на MVP; он является источником истины. Команды комнаты обрабатываются последовательно. Ведущий клиент не нужен.
- Состояния воспроизведения: `idle → preparing → playing → waiting_end`; пауза хранится отдельно и блокирует старт. Ошибки и ручной переход обрабатываются явно.
- Состояние комнаты: `roomId`, участники, `queue`, `currentEntryId`, `playbackId`, фаза, пауза, `startAt`, последняя позиция каждого клиента и `revision`. У каждой позиции очереди собственный ID, даже при повторении трека.
- Команды: `queue.add/remove/move`, `play`, `pause`, `next`. Отчёты клиента: `ready`, `position`, `ended`, `error`. Ответы: подтверждение команды и новое состояние с `revision`.
- Каждая команда содержит `commandId`, изменения очереди — ожидаемую `revision`. Повторы не выполняются дважды; конфликт возвращает актуальный снимок. События старого `playbackId` игнорируются, чтобы двойной `ended` не пропускал треки.
- По переподключении выдаётся полный снимок. Состояние участников и таймеры живут в памяти; после перезапуска очередь восстанавливается из SQLite, воспроизведение остаётся на паузе до подтверждения клиентов.
- Развёртывание: один контейнер приложения, постоянный том SQLite, reverse proxy с HTTPS/WSS. Аудио сервер не хранит и не ретранслирует.
- Проверять схемы команд, ограничивать частоту запросов и размер импорта. Токен комнаты непредсказуемый; токены и секреты SoundCloud остаются на сервере. Импорт принимает только разрешённые ссылки SoundCloud, без произвольной загрузки URL.

## Интеграция SoundCloud

Воспроизведение — официальный встроенный плеер с Widget API. Метаданные и полный состав коллекций — через серверный адаптер официального SoundCloud API; доступ приложения к API является зависимостью реализации. Альбомы и плейлисты проверяются отдельно на реальных ссылках. Поддержка публичного контента, доступного для встраивания; недоступность трека конкретному участнику показывается в интерфейсе.

Перед основной разработкой нужен небольшой прототип: проверить импорт полного альбома/плейлиста, запуск одиночного трека без самоперехода и поведение браузеров при следующем треке. Если браузер требует действие пользователя, показать «Включить звук» и до нажатия не считать клиента готовым. События плеера, вызванные серверной командой, не должны отправлять ту же команду обратно.

Документация: [Widget API](https://developers.soundcloud.com/docs/api/html5-widget), [SoundCloud API Guide](https://developers.soundcloud.com/docs/api/guide).

## Критерии приёмки

- Два клиента на Windows и Linux проходят сценарий совместного прослушивания в Chrome/Chromium и Firefox, включая смешанную пару браузеров.
- Трек, плейлист и альбом добавляются по ссылкам; порядок и полный состав доступных треков сохраняются.
- Play / Pause с любого клиента действуют на обоих; изменения очереди сходятся даже при одновременных командах.
- При искусственном отставании одного клиента на 3–5 секунд второй дослушивает и ждёт в тишине; следующий трек начинается совместно. Автокоррекций посреди трека нет.
- Проверены пауза во время ожидания, ручной переход, конец очереди, недоступный трек, отключение участника и повторное подключение. Комната не зависает навсегда.
- Обычное переключение окон не ломает очередь и управление; сон компьютера или длительная приостановка вкладки обрабатываются как потеря связи с последующим восстановлением.
- После перезапуска сервера очередь сохраняется, самопроизвольного запуска музыки нет.
