# sc/sync

Совместное прослушивание SoundCloud: комната по ссылке, общая очередь, общий старт каждого трека.
Звук идёт с SoundCloud напрямую каждому слушателю, сервер только координирует.

- `server/` — Rust (axum + tokio + SQLite). Источник истины: комнаты, очередь, барьеры готовности/окончания.
- `web/` — Svelte 5 + Vite. Встроенный плеер SoundCloud Widget, своё управление поверх него.
- `docs/PROTOCOL.md` — протокол клиент ↔ сервер и правила синхронизации.

## Как синхронизируется

Автоматической подгонки позиции и скорости посреди трека нет. Ручная перемотка по шкале общая для комнаты:
все готовятся к выбранной позиции и снова стартуют вместе. Вошедший посреди трека автоматически подключается
к текущей позиции. Звук запускается автоматически; если браузер требует жест пользователя,
достаточно обычного нажатия на страницу. Начальная громкость — 10, выбранное значение запоминается.
Сервер ждёт, пока все загрузят трек, и назначает общий `startAt` по своим часам; клиенты пересчитывают его через ping/pong.
Кто дослушал раньше, ждёт в тишине («ждём остальных»), отстающий спокойно доигрывает, и следующий трек снова стартует вместе.
От вечного ожидания защищают таймауты: готовность 20 с, дослушивание 30 с, потеря связи 15 с.

## Локальный запуск

```sh
# сервер, порт 8080
cd server && cp .env.example .env && cargo run --release

# клиент в режиме разработки, порт 5173, проксирует /api и /ws на 8080
cd web && npm install && npm run dev
```

Для одного процесса без Vite: `cd web && npm run build`, после этого сервер сам отдаёт `web/dist`.

Проверки: `cd server && cargo test && cargo clippy --all-targets -- -D warnings`, `cd web && npm run check`.

## SoundCloud API

Без ключа сервер работает через oEmbed: одиночные треки добавляются сразу, а плейлисты и альбомы клиент разворачивает
через второй скрытый виджет и передаёт серверу ID треков; сервер проверяет каждый через oEmbed.
Ограничения такого режима: нет длительности в очереди, альбомы помечаются как плейлисты.

С ключом (`SC_CLIENT_ID`, `SC_CLIENT_SECRET` в `.env`) используется официальный API: `/resolve`
и постраничное чтение коллекций до конца, причины недоступности треков и число пропавших позиций.

## Деплой

Один контейнер приложения и Caddy для HTTPS/WSS. SQLite лежит в томе `data`.

```sh
echo "DOMAIN=music.example.com" > .env   # без домена подойдёт <ip-через-дефисы>.sslip.io
docker compose up -d --build
```

Настройки сервера (таймауты, лимиты, ключи SoundCloud) описаны в `server/.env.example`; их можно добавить в тот же `.env`.

## Режим отладки интерфейса

В `npm run dev` можно открыть `/r/<любой-id>?mock=playing`, а также `join`, `blocked`, `waiting`, `empty` или `reconnecting`:
так комната показывается без сервера. В production-сборку это не попадает.
